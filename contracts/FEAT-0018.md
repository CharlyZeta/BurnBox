## Intent
Implementar la observabilidad y diagnóstico de salud del sistema según C-22 y C-23: health indicators dedicados de Spring Boot Actuator (KeyHealthIndicator y JobRunHealthIndicator), exposición de métricas operacionales en el puerto de gestión 8081 (/actuator/health, /actuator/info), estricta prohibición de fuga de material criptográfico o PII en Actuator, y reporte estructurado del estado de higiene y disponibilidad operativa.

## User Story
- Como: **Operador del sistema y SRE**
- Quiero: **inspeccionar la salud criptográfica y el estado de los jobs de higiene vía Actuator**
- Para: **monitorear la disponibilidad operativa y detectar anomalías sin comprometer la seguridad ni exponer material criptográfico**

## Use Case
**Actor:** Scraper de Monitoreo / SRE
**Goal:** Obtener el estado de salud operativa y disponibilidad de los componentes de Burnbox

### Main Flow
1. El scraper o SRE consulta GET /actuator/health en el puerto de gestión 8081.
2. KeyHealthIndicator verifica la disponibilidad de una versión activa de KEK y reporta status UP con el número de versión activa (sin exponer bytes de clave).
3. JobRunHealthIndicator consulta el estado de las últimas ejecuciones en job_run y reporta status UP si los jobs recientes completaron con SUCCESS o PARTIAL.
4. El endpoint consolida el estado global como UP y retorna JSON con código HTTP 200.
5. La consulta a /actuator/info expone versión de la aplicación y metadatos operativos básicos.

### Alternative Flows
- AF-01: Si no existe ninguna KEK activa en KeyProvider, KeyHealthIndicator reporta DOWN con detalle del error.
- AF-02: Si el último job_run de un job crítico falló con FAILED, JobRunHealthIndicator reporta DOWN informando el nombre del job.
- AF-03: Si la base de datos no responde, los health indicators dependientes degradan a DOWN con HTTP 503.
- AF-04: Si un cliente intenta invocar endpoints no autorizados, el puerto de gestión aplica las restricciones configuradas.

## Business Rules
- BR-001: **Cero exposición criptográfica en Actuator** — Los health indicators y métricas bajo /actuator tienen estrictamente prohibido emitir material de claves (KEKs o DEKs), hashes de tokens, sal o datos personales (PII).
- BR-002: **Aislamiento en puerto de gestión 8081** — Todos los endpoints de diagnóstico de Actuator se sirven exclusivamente a través del puerto de gestión dedicado (8081), separado del tráfico web principal (8080).
- BR-003: **Monitoreo de disponibilidad de KEK activa** — KeyHealthIndicator debe validar que keyProvider.getActiveVersion() > 0 y que existe una clave válida para cifrado.
- BR-004: **Auditoría de fallos de jobs** — JobRunHealthIndicator debe evaluar el historial reciente en job_run para alertar ante fallos acumulados en tareas de higiene o rotación.
- BR-005: **Resiliencia ante excepciones** — La consulta a un health indicator jamás debe provocar excepciones no controladas; cualquier fallo interno debe traducirse en un estado estructurado Health.down(e).
- BR-006: **Control estricto del tiempo** — Todo cálculo de ventanas temporales en indicadores de salud debe utilizar el bean Clock inyectado.

## Acceptance Criteria
- AC-001: GIVEN KEK activa configurada WHEN se consulta /actuator/health THEN reporta componente key con status UP y versión activa sin exponer bytes.
- AC-002: GIVEN ausencia de KEK activa WHEN se consulta KeyHealthIndicator THEN reporta status DOWN.
- AC-003: GIVEN ejecuciones recientes exitosas de jobs WHEN se consulta /actuator/health THEN reporta componente jobs con status UP.
- AC-004: GIVEN fallo en la última ejecución de un job crítico WHEN se consulta JobRunHealthIndicator THEN reporta status DOWN indicando el job afectado.
- AC-005: GIVEN consulta a /actuator/info WHEN responde THEN provee versión del sistema y metadatos de configuración sin secretos.
- AC-006: GIVEN puerto de gestión 8081 WHEN se envían peticiones a /actuator/health THEN responde con cabeceras de seguridad y status 200/503 según corresponda.
- AC-007: GIVEN respuesta completa de /actuator/health THEN ninguna clave KEK, DEK, salt, hash de token ni PII está presente en el cuerpo JSON.
- AC-008: GIVEN fallo al consultar base de datos en health check WHEN se ejecuta THEN captura la excepción y retorna Health DOWN limpiamente.

## Entities Affected
- `KeyHealthIndicator`: indicador de salud del anillo de KEKs en `com.burnbox.ops` o `com.burnbox.crypto`.
- `JobRunHealthIndicator`: indicador de salud del historial de ejecuciones de jobs en `com.burnbox.ops`.
- `job_run`: lectura de las últimas ejecuciones para diagnóstico de salud.
- `application.yaml`: configuración de Actuator `management.server.port: 8081`.
