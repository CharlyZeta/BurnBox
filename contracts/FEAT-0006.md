## Intent
Implementar la interfaz web SSR para la creación de secretos: formulario en la página principal con validación de tamaño de texto (hasta 64 KiB), selector de vencimiento (TTL) y límite de visualizaciones, endpoint POST /secrets con protección CSRF, y vista de confirmación que presenta el enlace de revelado una única vez con botón de copia.

## User Story
- Como: **Emisor de información confidencial**
- Quiero: **crear un secreto seguro mediante un formulario web definiendo su vigencia y visualizaciones**
- Para: **obtener un enlace de un solo uso que compartir con el destinatario sin exponer el contenido en claro**

## Depends On
- FEAT-0004, FEAT-0005

## Use Case
**Actor:** Emisor (visitante o usuario autenticado)
**Goal:** Introducir contenido sensible, configurar expiración y obtener el enlace único generado

### Main Flow
1. El emisor accede a `GET /` y visualiza el formulario de creación de secretos con campos para contenido, selector de TTL y límite de lecturas
2. El emisor ingresa el texto del secreto, selecciona TTL (5m, 1h, 1d, 7d) y max_views (1 a 10)
3. Envía el formulario mediante `POST /secrets` con token CSRF válido
4. `SecretWebController` valida las restricciones (texto no vacío, ≤ 64 KiB, TTL válido y max_views dentro de rango)
5. Invoca a `SecretService.createSecret()` pasando el comando con el usuario autenticado (o null si es anónimo)
6. El servicio cifra el contenido con AES-256-GCM, almacena en PostgreSQL y genera el token opaco de 43 caracteres
7. El controlador renderiza la vista de éxito `secret-created` mostrando el enlace completo `/s/{token}` una única vez
8. La respuesta incluye cabeceras `Cache-Control: no-store` y `X-Robots-Tag: noindex, nofollow`

### Alternative Flows
- AF-01: Envío con texto vacío o en blanco retorna al formulario con error de validación sin crear ningún secreto
- AF-02: Envío con contenido superior al límite de 64 KiB es rechazado con mensaje de tamaño excedido
- AF-03: Envío con TTL o max_views fuera de los rangos permitidos se rechaza con error de validación
- AF-04: Petición sin token CSRF válido es rechazada con código HTTP 403 Forbidden

## Business Rules
- BR-001: **Límite estricto de carga útil** — el texto del secreto en claro no puede superar los 65.536 bytes (64 KiB); valores mayores son rechazados inmediatamente
- BR-002: **Catálogo controlado de TTL** — la expiración solo admite duraciones explícitas preconfiguradas (5 minutos, 1 hora, 1 día, 7 días); prohibidos valores arbitrarios o infinitos
- BR-003: **Límite acotado de visualizaciones** — el parámetro `max_views` debe ser un entero entre 1 y 10; el valor por defecto es 1
- BR-004: **Enlace expuesto una sola vez** — el enlace con el token en claro `/s/{token}` solo se entrega en la respuesta directa del POST de creación; nunca se reenvía por correo ni se puede recuperar del servidor
- BR-005: **Protección CSRF obligatoria** — todo `POST /secrets` requiere token CSRF válido; peticiones sin token o con token alterado son bloqueadas
- BR-006: **Antialmacenamiento estricto** — la vista del enlace generado incluye cabeceras `Cache-Control: no-store` y `X-Robots-Tag: noindex, nofollow` para evitar indexación o guardado en caché
- BR-007: **Atribución de propietario** — si el emisor cuenta con sesión autenticada, `owner_user_id` registra su UUID; si es anónimo, se registra `null`

## Acceptance Criteria
- AC-001: GIVEN solicitud `GET /` WHEN se renderiza la página principal THEN muestra el formulario de creación con selector de TTL, max_views y token CSRF
- AC-002: GIVEN formulario con texto de 1 KiB, TTL 1 hora y max_views 1 WHEN `POST /secrets` se procesa THEN responde 200 y renderiza `secret-created` con el enlace `/s/{token}`
- AC-003: GIVEN envío con texto en blanco WHEN `POST /secrets` se ejecuta THEN responde con formulario y mensaje de error sin persistir en base
- AC-004: GIVEN envío con texto que excede 64 KiB WHEN `POST /secrets` se ejecuta THEN rechaza con error de tamaño máximo excedido
- AC-005: GIVEN envío con TTL inválido o negativo WHEN `POST /secrets` se ejecuta THEN rechaza con error de validación
- AC-006: GIVEN envío con max_views menor a 1 o mayor a 10 WHEN `POST /secrets` se ejecuta THEN rechaza con error de validación
- AC-007: GIVEN respuesta de `secret-created` WHEN se examinan cabeceras HTTP THEN contiene `Cache-Control: no-store` y `X-Robots-Tag: noindex, nofollow`
- AC-008: GIVEN usuario autenticado en sesión WHEN crea un secreto THEN el secreto persistido contiene su `owner_user_id`
