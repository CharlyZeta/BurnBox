## Intent
Implementar el módulo `ratelimit` con soporte para token buckets configurados según la especificación: revelado por prefijo de IP (`reveal-ip`, 20 req/min), revelado por token (`reveal-token`, 10 req/min), creación por IP (`create-ip`, 30 req/hora), respuesta HTTP 429 uniforme con cabecera `Retry-After` que no revele qué bucket disparó el límite, y detección de abuso (10 tokens fallidos en 5 min -> bloqueo temporal por 1 hora con publicación de evento `AbuseIpFlagged`).

## User Story
- Como: **Operador del servicio Burnbox**
- Quiero: **proteger los endpoints de revelado y creación contra escaneo de tokens, fuerza bruta y abuso de peticiones**
- Para: **mitigar ataques de denegación de servicio y adivinación de secretos manteniendo respuestas 429 uniformes sin fuga de información**

## Depends On
- FEAT-0001, FEAT-0003, FEAT-0004, FEAT-0005, FEAT-0006

## Use Case
**Actor:** Visitante (anónimo o atacante)
**Goal:** Realizar peticiones de revelado o creación dentro de las tasas permitidas o ser mitigado uniformemente

### Main Flow
1. El cliente envía una petición HTTP a un endpoint protegido (`POST /secrets`, `GET /s/{token}`, `POST /s/{token}/reveal`).
2. El sistema extrae la clave correspondiente (prefijo de IP cliente normalizado o hash del token).
3. El sistema evalúa el bucket asociado contra el límite configurado.
4. Si hay tokens disponibles, se consume uno y la petición continúa al controlador de negocio.

### Alternative Flows
- AF-01: Si no hay tokens disponibles en el bucket, el sistema retorna HTTP 429 con cabecera Retry-After sin revelar qué bucket se agotó
- AF-02: Si la IP del cliente se encuentra en la ventana de bloqueo de 1 hora por abuso, el sistema rechaza inmediatamente la petición con HTTP 429 uniforme
- AF-03: Si un prefijo de IP acumula 10 fallos de token en 5 minutos, el sistema registra un bloqueo de 1 hora y publica AbuseIpFlagged
- AF-04: Si la petición incluye X-Forwarded-For, solo se extrae si el origen remoto es un proxy local confiable configurado

## Business Rules
- BR-001: Configuración de buckets — límites son reveal-ip = 20/minuto, reveal-token = 10/minuto, create-ip = 30/hora
- BR-002: Respuesta uniforme 429 — toda respuesta por exceso de tasa debe retornar HTTP 429 con cabecera Retry-After indicando segundos enteros
- BR-003: Normalización de prefijo IP — IPv4 se agrupa en /24 e IPv6 en /64 para evitar elusión por rotación de interfaces
- BR-004: Umbral de detección de abuso — 10 o más intentos fallidos de tokens distintos desde un mismo prefijo de IP en 5 minutos activan bloqueo de 1 hora
- BR-005: Publicación de evento de abuso — al activarse un bloqueo por abuso, se publica AbuseIpFlagged sin almacenar secretos ni PII
- BR-006: Control temporal inyectado — todo cálculo de tiempo, expiración y tokens se resuelve mediante el Clock inyectado

## Acceptance Criteria
- AC-001: Peticiones dentro de la tasa permitida en reveal-ip y create-ip retornan el resultado habitual del endpoint
- AC-002: La petición número 21 en menos de un minuto desde el mismo prefijo de IP a /s/** retorna HTTP 429
- AC-003: La respuesta 429 incluye cabecera Retry-After con valor entero positivo mayor o igual a 1
- AC-004: Más de 10 peticiones en menos de un minuto contra el mismo hash de token retornan HTTP 429
- AC-005: Más de 30 peticiones de creación en menos de una hora desde la misma IP retornan HTTP 429
- AC-006: El cuerpo de la respuesta 429 es genérico y no contiene nombres de bucket, cuotas ni datos internos
- AC-007: Al acumularse 10 fallos de revelado con tokens distintos en 5 minutos desde un prefijo IP, peticiones subsecuentes reciben 429 por 1 hora
- AC-008: Al activarse el bloqueo de abuso, el sistema emite AbuseIpFlagged capturado por escuchas de eventos

## Inferred Assumptions
- **AS-01 (In-Memory con soporte Clock inyectado):** La gestión de buckets en el módulo `ratelimit` se estructura en memoria con sincronización concurrente thread-safe gobernada por el `Clock` inyectado, respetando la modularidad de Spring Modulith.
  - Confirmed: Sí, implementado en capa de servicio y filtro web.
