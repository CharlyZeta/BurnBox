## Intent
Implementar la cadena criptográfica de auditoría inmutable en security_event según C-15: cálculo determinista de hash encadenado SHA-256 (prev_hash y hash), protección contra bifurcación mediante restricción de unicidad UNIQUE(prev_hash), trigger PostgreSQL que impone inmutabilidad estricta (prohibiendo UPDATE y DELETE), verificador de integridad de la cadena y vista web SSR /account/events para que los usuarios autenticados consulten sus propios eventos de seguridad.

## User Story
- Como: **Oficial de seguridad o usuario autenticado**
- Quiero: **auditar eventos de seguridad mediante una cadena criptográfica de hashes inmutable**
- Para: **detectar de forma infalible cualquier manipulación o borrado no autorizado en los registros de auditoría**

## Use Case
**Actor:** Subsistema de auditoría y Usuario autenticado
**Goal:** Registrar eventos con hash encadenado y verificar la integridad de la cadena

### Main Flow
1. Un componente del sistema emite un evento de seguridad a través de SecurityEventPublisher.
2. SecurityEventRepository obtiene el hash del último evento registrado o el bloque génesis si es el primero.
3. El repositorio calcula el hash del nuevo evento aplicando SHA-256 determinista sobre los campos canónicos del evento.
4. El nuevo evento se persiste atómicamente con su prev_hash y hash calculados.
5. El verificador AuditChainVerifier recorre secuencialmente la cadena recalculando cada hash y validando el encadenamiento.
6. El usuario autenticado accede a GET /account/events para visualizar el registro de sus eventos de seguridad personales.

### Alternative Flows
- AF-01: Intento directo de ejecutar UPDATE o DELETE sobre security_event es abortado por el trigger de base de datos con excepción de inmutabilidad.
- AF-02: Intento de insertar una bifurcación con un prev_hash ya existente es rechazado por la restricción de unicidad UNIQUE(prev_hash).
- AF-03: Verificación de integridad detecta un registro con hash recalculado discrepante o prev_hash alterado y reporta estado Broken.
- AF-04: Visitante anónimo que accede a GET /account/events es redirigido a /login.

## Business Rules
- BR-001: **Estructura de hash encadenado** — Cada evento en security_event debe incluir prev_hash (hash del evento precedente, o 64 ceros si es el evento génesis) y hash calculado como SHA-256 hexadecimal de sus campos canónicos.
- BR-002: **Prohibición de bifurcación (no-forking)** — La columna prev_hash debe poseer restricción unívoca UNIQUE(prev_hash) en la base de datos para impedir que dos registros sucesivos compartan el mismo bloque padre.
- BR-003: **Inmutabilidad estricta append-only** — La tabla security_event debe contar con un trigger PostgreSQL que rechace irrevocablemente cualquier operación de UPDATE o DELETE.
- BR-004: **Determinismo del hash** — El cálculo del hash debe ser canónico y determinista aplicando SHA-256 sobre prev_hash, epochMilli, eventType, actorUserId, subjectType, subjectId, requestId, ipHash y details.
- BR-005: **Verificación integral de cadena** — AuditChainVerifier debe validar la integridad secuencial de la cadena desde el génesis hasta la cabeza, reportando cualquier alteración detectada con el ID del evento afectado.
- BR-006: **Aislamiento de eventos de usuario** — La vista /account/events solo presenta eventos donde actor_user_id coincida con el usuario autenticado actual, preservando confidencialidad entre cuentas y sin filtrar datos de infraestructura.

## Acceptance Criteria
- AC-001: GIVEN el primer evento del sistema WHEN se persiste THEN prev_hash se establece como 64 ceros y hash se calcula correctamente con SHA-256.
- AC-002: GIVEN un evento subsiguiente WHEN se persiste THEN su prev_hash coincide exactamente con el hash del evento anterior.
- AC-003: GIVEN base de datos PostgreSQL WHEN se intenta ejecutar UPDATE o DELETE sobre security_event THEN el trigger lanza excepción abortando la transacción.
- AC-004: GIVEN intento de inserción con prev_hash duplicado WHEN se ejecuta THEN la restricción de unicidad rechaza la operación.
- AC-005: GIVEN una cadena intacta WHEN AuditChainVerifier.verifyChain() se ejecuta THEN devuelve resultado Valid.
- AC-006: GIVEN una fila en la base con datos alterados WHEN AuditChainVerifier.verifyChain() se ejecuta THEN devuelve Broken identificando el ID comprometido.
- AC-007: GIVEN usuario autenticado WHEN accede a GET /account/events THEN visualiza la lista de sus eventos personales ordenados cronológicamente sin PII expuesta.
- AC-008: GIVEN visitante anónimo WHEN accede a GET /account/events THEN es redirigido a /login.

## Entities Affected
- `security_event`: constraint `UNIQUE(prev_hash)` y trigger `trg_security_event_append_only`.
- `SecurityEventRepository`: lógica de encadenamiento `prev_hash` -> `hash`.
- `AuditChainVerifier`: servicio de verificación secuencial de la cadena.
- `AuditController`: vista SSR `/account/events`.
